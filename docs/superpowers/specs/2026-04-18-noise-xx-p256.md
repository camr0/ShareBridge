# noise-p256 — Noise_XX_P256_AESGCM_SHA256 Library Spec

**Date:** 2026-04-18
**Status:** Approved for implementation

---

## Purpose

A standalone, zero-dependency Noise_XX implementation using P-256 + AES-256-GCM + SHA-256. Designed as the E2E encryption layer for the ShareBridge e2ecp-style relay — the relay forwards ciphertext it cannot read, and this library is what runs inside the endpoints.

Built dual-language (JS + Go) so the browser and agent share identical handshake semantics. Modular enough to publish as an open-source library later.

**Out of scope:** framing, backpressure, stream abstraction, transport (WebSocket/WebTransport). The library operates on byte slices; the caller is responsible for sending/receiving them.

---

## Cipher Suite

`Noise_XX_P256_AESGCM_SHA256`

| Component | Choice | Rationale |
|---|---|---|
| DH | P-256 ECDH | Native in Web Crypto API and Go stdlib; no deps |
| Cipher | AES-256-GCM | AES-NI hardware acceleration; native in Web Crypto API |
| Hash | SHA-256 | Native everywhere; matches HASHLEN=32 |
| Pattern | XX | Both parties authenticate; standard mutual-auth pattern |

All three primitives have native browser implementations (`crypto.subtle`) — no WebAssembly, no bundled cryptography.

---

## Protocol Name and Initialization

The protocol name string is: `Noise_XX_P256_AESGCM_SHA256`

**Length:** 27 bytes.

Because `len("Noise_XX_P256_AESGCM_SHA256") = 27 ≤ HASHLEN (32)`, the Noise spec (§5.2) requires **zero-padding** — not hashing.

```
h  = "Noise_XX_P256_AESGCM_SHA256" || 0x00 0x00 0x00 0x00 0x00  (32 bytes total)
ck = h
```

**`initialize()` must set both `h` and `ck` to this same 32-byte value.** Both must be returned/stored — GLM5's version only returned `h`.

After setting `h` and `ck`, each party calls `MixHash(prologue)` where `prologue` is the empty byte sequence `b""` (no prologue for ShareBridge). This is a no-op but must be callable for spec compliance.

---

## Noise_XX Handshake Pattern

The standard Noise_XX token sequence (Noise spec §7):

```
XX:
  -> e
  <- e, ee, s, es
  -> s, se
```

**Message 1** (initiator → responder): `e`
**Message 2** (responder → initiator): `e, ee, s, es`
**Message 3** (initiator → responder): `s, se`

Each message may carry an application payload. This library always uses an **empty payload** during the handshake; the 16-byte AEAD tag is still present for messages 2 and 3 (see Wire Format).

---

## Token Semantics

The Noise spec uses different DH roles depending on who is processing the token. For XX in ShareBridge: **initiator = browser**, **responder = agent**.

| Token | Initiator processes | Responder processes |
|---|---|---|
| `e` (send) | Generate `(ie_priv, ie_pub)`, `MixHash(ie_pub)` | Generate `(re_priv, re_pub)`, `MixHash(re_pub)` |
| `e` (recv) | `MixHash(re_pub)` | `MixHash(ie_pub)` |
| `ee` | `MixKey(DH(ie_priv, re_pub))` | `MixKey(DH(re_priv, ie_pub))` |
| `s` (send) | `EncryptAndHash(is_pub)` → send 81 bytes | `EncryptAndHash(rs_pub)` → send 81 bytes |
| `s` (recv) | decrypt 81 bytes → `rs_pub` | decrypt 81 bytes → `is_pub` |
| `es` | `MixKey(DH(ie_priv, rs_pub))` | `MixKey(DH(rs_priv, ie_pub))` |
| `se` | `MixKey(DH(is_priv, re_pub))` | `MixKey(DH(re_priv, is_pub))` |

`e` keys are ephemeral (generated fresh per session). `s` keys are static (agent long-lived; browser per-session ephemeral).

## Message Processing — Step by Step

### Message 1 — initiator sends

```
1. Generate ephemeral key pair: (ie_priv, ie_pub)
2. MixHash(ie_pub)                         // token: e
3. Wire: ie_pub (65 bytes)
```

### Message 2 — responder sends

```
1. Generate ephemeral key pair: (re_priv, re_pub)
2. MixHash(re_pub)                         // token: e
3. Wire: re_pub (65 bytes)
4. ee = DH(re_priv, ie_pub)
5. MixKey(ee)                              // token: ee  — k is now set
6. EncryptAndHash(rs_pub)                  // token: s   — encrypts static key
7. Wire: encrypted_rs_pub (81 bytes)
8. es = DH(rs_priv, ie_pub)
9. MixKey(es)                              // token: es
10. EncryptAndHash(b"")                    // empty payload
11. Wire: payload_tag (16 bytes)
```

### Message 2 — initiator receives

```
1. Read re_pub (65 bytes); MixHash(re_pub)  // token: e
2. ee = DH(ie_priv, re_pub)
3. MixKey(ee)                               // token: ee  — k is now set
4. Read 81 bytes; rs_pub = DecryptAndHash(81 bytes)  // token: s
5. es = DH(ie_priv, rs_pub)
6. MixKey(es)                               // token: es
7. Read 16 bytes; DecryptAndHash(b"")       // empty payload — verify AEAD tag
```

### Message 3 — initiator sends

```
1. EncryptAndHash(is_pub)                   // token: s
2. Wire: encrypted_is_pub (81 bytes)
3. se = DH(is_priv, re_pub)
4. MixKey(se)                               // token: se
5. EncryptAndHash(b"")                      // empty payload
6. Wire: payload_tag (16 bytes)
```

### Message 3 — responder receives

```
1. Read 81 bytes; is_pub = DecryptAndHash(81 bytes)  // token: s
2. se = DH(re_priv, is_pub)
3. MixKey(se)                               // token: se
4. Read 16 bytes; DecryptAndHash(b"")       // verify AEAD tag
```

## Wire Format

All messages are sent as raw byte sequences. The **caller** is responsible for framing (ShareBridge uses a 5-byte length-prefix header before every message). Within a handshake message the bytes are concatenated with no separators.

| Message | Bytes | Breakdown |
|---|---|---|
| Message 1 | 65 | `ie_pub` (65) |
| Message 2 | 162 | `re_pub` (65) + `EncryptAndHash(rs_pub)` (81) + `EncryptAndHash(b"")` (16) |
| Message 3 | 97 | `EncryptAndHash(is_pub)` (81) + `EncryptAndHash(b"")` (16) |

P-256 public keys are always **uncompressed form**: `0x04 || x (32 bytes) || y (32 bytes)` = 65 bytes.

AES-256-GCM appends a 16-byte authentication tag to the ciphertext. A 65-byte plaintext (public key) produces 81 bytes of ciphertext. A 0-byte plaintext produces 16 bytes.

## Correctness Notes (deviations from GLM5 design, corrected here)

1. **Protocol name is 27 bytes, not 28.** Padding is 5 zero bytes, not 4.
2. **`initialize()` must set both `h` and `ck`.** GLM5's version only returned `h`.
3. **Noise_XX message 2 includes `s, es` tokens.** GLM5 omitted these, describing a non-standard pattern where the responder never authenticates itself. The standard XX mutually authenticates both parties.
4. **`Split()` input is `b""` (zero-length), not `zeros(32)`.** GLM5 used `zeros(32)` which deviates from the spec and would produce different keys than any conforming implementation.
5. **AES-GCM nonce is `0x00000000 || n_uint64_be`, not just `n`.** The nonce is 12 bytes: 4 zero bytes + 8-byte big-endian counter.
6. **`MixHash` is called with ciphertext, not plaintext, in both `EncryptAndHash` and `DecryptAndHash`.** This is how both parties stay in sync.

## Cryptographic Operations

### DH(private_key, public_key)

P-256 ECDH. Returns the raw 32-byte shared secret (x-coordinate of the point, big-endian). The y-coordinate is discarded.

- **JS:** `crypto.subtle.deriveBits({ name: "ECDH", public: public_key }, private_key, 256)` → `ArrayBuffer` (32 bytes)
- **Go:** `(*ecdh.PrivateKey).ECDH(public_key)` → `[]byte` (32 bytes)

### MixHash(data)

```
h = SHA-256(h || data)
```

Pure function on `h`. No key material involved.

### MixKey(input_key_material)

Uses Noise's HKDF (§4.2 of Noise spec):

```
temp_key = HMAC-SHA256(key=ck, data=input_key_material)
output1  = HMAC-SHA256(key=temp_key, data=0x01)
output2  = HMAC-SHA256(key=temp_key, data=output1 || 0x02)
ck = output1       // new chaining key
k  = output2       // new cipher key (32 bytes)
n  = 0             // reset nonce counter
```

`ck` and `k` are always 32 bytes (HASHLEN = 32 for SHA-256, no truncation needed).

### EncryptWithAd(ad, plaintext)

AES-256-GCM with the current cipher key `k` and nonce `n`:

```
nonce_bytes = 0x00 0x00 0x00 0x00 || n_as_uint64_big_endian  // 12 bytes total
ciphertext  = AES-256-GCM-Encrypt(key=k, nonce=nonce_bytes, aad=ad, plaintext=plaintext)
n           = n + 1
return ciphertext   // len(plaintext) + 16 bytes
```

The nonce is a 12-byte value: 4 zero bytes followed by the 8-byte big-endian encoding of the 64-bit counter.

**Fatal error if k is zero (uninitialized).** The library must panic/throw if encrypt is called before a MixKey has initialized k.

### DecryptWithAd(ad, ciphertext)

AES-256-GCM decrypt. Same nonce construction as above. Increments `n` on success. Throws/returns error on authentication failure — **do not increment n on failure**.

### EncryptAndHash(plaintext)

```
ciphertext = EncryptWithAd(ad=h, plaintext=plaintext)
MixHash(ciphertext)
return ciphertext
```

### DecryptAndHash(ciphertext)

```
plaintext = DecryptWithAd(ad=h, ciphertext=ciphertext)
MixHash(ciphertext)
return plaintext
```

Note: `MixHash` is called with the **ciphertext** (not the plaintext) in both directions, so both parties update their transcript hash identically.

### Split() — derive post-handshake keys

Called once by both parties after message 3 is complete. Uses Noise's HKDF with **empty input** (zerolen = `b""`):

```
temp_key = HMAC-SHA256(key=ck, data=b"")        // zerolen, NOT zeros(32)
k1       = HMAC-SHA256(key=temp_key, data=0x01)
k2       = HMAC-SHA256(key=temp_key, data=k1 || 0x02)
return (k1, k2)   // each 32 bytes
```

`k1` is the initiator→responder cipher key (browser→agent).
`k2` is the responder→initiator cipher key (agent→browser).

Each key has its own independent nonce counter starting at 0.

**GLM5 bug to avoid:** Split input is `b""` (zero-length), **not** `zeros(32)`. GLM5's design used `zeros(32)` which is a non-standard deviation.

## State Machine

Each `NoiseXX` instance tracks:

```
h        [32]byte    // transcript hash
ck       [32]byte    // chaining key
k        [32]byte    // cipher key (zero until first MixKey)
n        uint64      // nonce counter for handshake AEAD
role     enum        // Initiator | Responder
phase    enum        // Uninitialized | Message1Sent | Message2Sent | Message3Sent | Done
ie_priv  key         // initiator ephemeral private (set during WriteMessage1)
ie_pub   key         // initiator ephemeral public
re_pub   key         // responder ephemeral public (set during ReadMessage2 / WriteMessage2)
rs_pub   key         // responder static public (set during ReadMessage2)
is_priv  key         // initiator static private (provided at construction)
is_pub   key         // initiator static public
rs_priv  key         // responder static private (provided at construction for responder)
```

State transitions:

```
Uninitialized ──initialize()──> Ready
Ready (initiator) ──WriteMessage1()──> Msg1Sent
Msg1Sent ──ReadMessage2()──> Msg2Received
Msg2Received ──WriteMessage3()──> Done
Ready (responder) ──ReadMessage1()──> Msg1Received
Msg1Received ──WriteMessage2()──> Msg2Sent
Msg2Sent ──ReadMessage3()──> Done
```

Calling methods out of order is a programming error: throw/panic.

## Static Key Management

**Agent (responder):** Generates a P-256 key pair on first startup; persists to disk (e.g. `~/.sharebridge/relay_static.pem`). The public key is included in `relay_info` messages sent to browsers via the signaling server.

**Browser (initiator):** Generates a fresh P-256 key pair per relay session using `crypto.subtle.generateKey`. Not persisted. The browser's static key is per-session ephemeral — it exists only to complete the XX pattern; the agent does not remember it.

**Static key binding to JWT:** The `relay_info` message from the signaling server includes `agent_static_pub` (65-byte hex). After receiving message 2, the browser MUST verify that `rs_pub` from the handshake equals `agent_static_pub`. If they differ, the connection MUST be torn down immediately — this indicates a MITM (e.g. a compromised relay).

## Post-Handshake Encryption

After `Split()`, the library provides two independent cipher states:

```go
// Go
type CipherState struct {
    key [32]byte
    n   uint64
}

func (c *CipherState) Encrypt(ad, plaintext []byte) ([]byte, error)
func (c *CipherState) Decrypt(ad, ciphertext []byte) ([]byte, error)
```

```js
// JS
class CipherState {
    async encrypt(ad, plaintext)  // returns Uint8Array
    async decrypt(ad, ciphertext) // returns Uint8Array (throws on auth failure)
}
```

The caller passes `ad = b""` for the ShareBridge file transfer (no associated data needed post-handshake). Nonce is managed internally and must never be reused. If n reaches `2^64 - 1`, the cipher state is exhausted — the library must throw/panic rather than wrap.

## API Contract

### JavaScript

```js
import { NoiseXX } from './noise-p256/index.js'

// Initiator (browser)
const noise = await NoiseXX.createInitiator()
// noise.staticPub: Uint8Array (65 bytes) — browser's per-session static pub key

const msg1 = await noise.writeMessage1()   // Uint8Array, 65 bytes
// ... send msg1 to relay, receive msg2 ...

await noise.readMessage2(msg2)             // Uint8Array, 162 bytes; throws on auth failure
// noise.remoteStaticPub: Uint8Array (65 bytes) — agent's static pub key
// caller MUST check noise.remoteStaticPub against relay_info.agent_static_pub

const msg3 = await noise.writeMessage3()   // Uint8Array, 97 bytes
// ... send msg3 ...

const [send, recv] = noise.split()
// send: CipherState (browser→agent)
// recv: CipherState (agent→browser)

// Post-handshake
const ct = await send.encrypt(new Uint8Array(0), plaintext)
const pt = await recv.decrypt(new Uint8Array(0), ciphertext)

// Responder (for test cross-checking — not browser production code)
const agent = await NoiseXX.createResponder(staticPrivKey)
await agent.readMessage1(msg1)
const msg2 = await agent.writeMessage2()
await agent.readMessage3(msg3)
const [agentRecv, agentSend] = agent.split()
```

### Go

```go
// Initiator (for test cross-checking)
noise, err := noise.NewInitiator()
msg1, err := noise.WriteMessage1()
err = noise.ReadMessage2(msg2)
// noise.RemoteStaticPub() []byte  — verify against relay_info
msg3, err := noise.WriteMessage3()
send, recv := noise.Split()

// Responder (agent)
noise, err := noise.NewResponder(staticPrivKey)
err = noise.ReadMessage1(msg1)
msg2, err := noise.WriteMessage2()
err = noise.ReadMessage3(msg3)
recvFromBrowser, sendToBrowser := noise.Split()

// Post-handshake
ct, err := sendToBrowser.Encrypt(nil, plaintext)
pt, err := recvFromBrowser.Decrypt(nil, ciphertext)
```

`Split()` returns `(send, recv)` from the perspective of the calling party:
- Initiator split → `(send=k1, recv=k2)`
- Responder split → `(send=k2, recv=k1)`

This means both parties call `send.Encrypt` for outbound and `recv.Decrypt` for inbound — no role-tracking needed after Split.

## Test Vector Strategy

### Phase 1 — development vectors

During initial implementation, generate consistent test vectors by fixing deterministic key material:

```
ie_priv: aaaa...aa (32 bytes, P-256 scalar — use a well-known test value)
rs_priv: bbbb...bb
is_priv: cccc...cc
re_priv: dddd...dd
```

Use these to verify `h`, `ck`, and each wire message at every step. This catches implementation divergence between Go and JS quickly.

### Phase 2 — official spec vectors

Before shipping, verify against the official Noise test vectors from noise-protocol.org (the `cacophony` test vector file, JSON format). The relevant suite is `Noise_XX_25519_AESGCM_SHA256` — **not P-256**, because P-256 is not in the standard test vector file.

Since no official vectors exist for `Noise_XX_P256_AESGCM_SHA256`, the alternative is to use the `cacophony` vectors for a different suite to verify the **transcript and HKDF logic** is correct (the hash chaining is suite-independent), then verify the P-256 DH output with NIST CAVP P-256 ECDH test vectors separately.

**Cross-language interop test:** The primary correctness gate is that a JS initiator can complete a handshake with a Go responder and decrypt a payload. This test must be run in CI.

## Security Properties

After a successful handshake, the session provides:

- **Forward secrecy:** Ephemeral DH keys are discarded after use. Compromise of the agent's static key does not reveal past session content.
- **Mutual authentication:** The browser authenticates the agent (static key pinned via `relay_info`). The agent authenticates that someone completed the XX handshake (browser static pub received but not pinned — JWT auth covers the authorization).
- **MITM prevention:** The relay forwards ciphertext. It does not participate in the Noise handshake and cannot impersonate the agent without its static private key. The browser verifies `rs_pub == relay_info.agent_static_pub` to confirm it reached the intended agent.
- **Replay protection:** AES-GCM with monotonic nonce. Each post-handshake message is uniquely authenticated. Replaying a ciphertext fails because the nonce counter has already advanced.
- **Nonce exhaustion:** If either cipher state's nonce counter reaches `2^64 - 1`, the library panics/throws. The caller must not reach this limit — a 1 GiB/s sustained transfer would take ~146 years at 16 KiB frames.

## Integration with ShareBridge Relay

This library sits between the WebSocket connection and the file transfer protocol. The calling code handles framing.

```
Browser WebSocket send path:
  [file chunk] → noise.send.encrypt(b"", chunk) → [5-byte length prefix] + [ciphertext] → WebSocket.send()

Browser WebSocket recv path:
  WebSocket.onmessage → strip 5-byte prefix → noise.recv.decrypt(b"", ciphertext) → [file chunk]
```

The handshake itself uses the same 5-byte framing:

```
Browser → relay → agent: [5-byte length=65] + [msg1]
Agent → relay → browser: [5-byte length=162] + [msg2]
Browser → relay → agent: [5-byte length=97] + [msg3]
```

The relay does not know about Noise — it forwards bytes in both directions without inspection. JWT validation happens in a separate HTTP upgrade/auth step before the relay circuit opens.
